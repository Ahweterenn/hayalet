> The codebase, comments, and user-facing strings are in **Turkish**. Match that language when editing comments and CLI output.

## What this is

`hayalet` is a headless (browser-less), pure-Python terminal tool for watching/downloading from Turkish streaming sites, selectable via `--site`. Five sites are registered as of this writing: **Dizipal** (TV series), **hdfilmcehennemi.nl** (movies + series), **diziyou.one**, **fullhdfilmizlesene.now**, and **webdramaturkey2.com** — see `hayalet/sites/*_adapter.py` for the current list (`hayalet.core.sites.SITES`). It bypasses Cloudflare/anti-bot via TLS impersonation, searches, navigates seasons/episodes (or resolves a movie directly), resolves the `m3u8` stream + Turkish subtitle, then either **watches** (browser + hls.js) or **downloads** (ffmpeg mux). The Dizipal-specific scraping/decryption logic is a Python port of a browser extension that lives in `reference/örnek eklenti/` — the ad blacklist and the media/subtitle heuristics come straight from that extension (`content.js`, `page-inject.js`).

Adding another site means writing one new `hayalet/sites/<name>_adapter.py` (see **Multi-site adapter layer** below) — the shared pipeline (session/network, HLS proxy, ffmpeg mux, menu flow) never forks per site.

## Commands

Setup (Windows; venv already present in repo):
```bash
cd hayalet
python -m venv venv
venv\Scripts\activate          # PowerShell: venv\Scripts\Activate.ps1
pip install -r requirements.txt
# or: pip install -e .   (installs the `hayalet` console entry point)
```

Run:
```bash
python -m hayalet                                   # interactive menu (recommended)
baslat.bat                                          # Windows launcher (sets UTF-8, uses venv python)

# Non-interactive / automation:
python -m hayalet --search "house of the dragon"    # list results with indices (default --site dizipal)
python -m hayalet --search "..." --series 1 --season 1 --episode 1 --action extract
python -m hayalet --search "..." --series 1 --season 1 --episode 1 --action watch
python -m hayalet --search "..." --series 1 --season 1 --episodes 1,2,3 --action download
python -m hayalet --domain https://dizipalXXXX.com  # skip the resolver, pin a domain
python -m hayalet --site hdfilmcehennemi --search "matrix" --series 0 --action extract   # movie site
python -m hayalet --doctor                          # live health check: domain/search/episodes/extract per site (or --site to pin one)
# Cloudflare JS challenge ("Just a moment...") — hand over a browser-obtained cookie.
# cf_clearance is bound to the issuing browser's UA *and* IP, so --user-agent is mandatory
# (argparse enforces it) and passing it disables persona rotation for that run.
# Pass it ONCE: the pair is persisted per-host in prefs.json and reloaded automatically on
# later runs (`prefs.save_cf`/`load_cf`), so no flags are needed until it expires — at which
# point the site challenges again, `_connect` deletes the stale record and asks for a new one:
python -m hayalet --site hdfilmcehennemi --cf-cookie "cf_clearance=..." --user-agent "Mozilla/5.0 ..." --doctor
python -m hayalet --site hdfilmcehennemi --search "matrix" --series 0 --action extract   # sonrası bayraksız
```

`--quality` only affects `--action extract` output; **downloads always grab the highest-quality variant** (see `actions.download` below) — no quality prompt exists anymore.

There is **no linter or build step**. There is a small pure-logic **test suite** (`tests/`, pytest — install with `pip install -e ".[test]"`, run with `pytest`): decrypt_rmk / hdfilmcehennemi packer+unmix (against real, frozen fixtures captured live in `tests/fixtures/`), `match_episode`/`next_episode`, `safe_filename`, `m3u8_parser` (against a fake in-memory `Network`, no HTTP), `test_query.py` (search normalization/variants/ranking — see **Tolerant search** below), `test_subsync.py` (subtitle↔audio alignment: VTT timestamp parsing in both `MM:SS.mmm` and `HH:MM:SS.mmm` forms, known-offset recovery, the refusals, and `shift_vtt` round-trips — the live measurement's behaviour locked in against regression), and `test_vtt_map.py` (first-PTS reading and `X-TIMESTAMP-MAP` insertion), `test_doctor.py` (`--doctor` must go red when series episode lists are empty even if a movie works — it used to check the first result, often a movie, whose single synthetic episode always "lists"; it now validates on a series first and says so when a site returns only movies), `test_resilience.py` (mirror detection, Cloudflare-challenge detection, `--cf-cookie` parsing, plus `resolver.resolve` end-to-end against a **fake in-memory internet** — rollover past the old scan window, canonical-following, mirror-origin preference, rejecting a reachable-but-search-dead address, and "cache hit must not trigger a scan"). These are network-free and answer "did *our code* regress" — they do **not** verify the site itself still works that way; use `python -m hayalet --doctor` for that (live, network-bound: domain → search → episode list → end-to-end extract, per site). Beyond that, verification is manual: run `--action extract` (cheapest, network-only, no player/ffmpeg) to confirm the extraction chain still works end-to-end. **Player-page (`proxy._PLAYER_TEMPLATE`) changes can't be verified this way** — they need a real browser: syntax-check the extracted JS with `node --check`, and for behavior (menu, keyboard, subtitle rendering) drive a headless Chromium ad-hoc with Playwright (`pip install playwright` + `playwright install chromium`, then uninstall — it is **not** a project dependency).

External tools (auto-detected via `shutil.which` + known install paths in `actions.py`):
- **ffmpeg** — required for `download` (must be on PATH).
- A browser — `watch` opens `webbrowser.open` on the local proxy's `/player.html`.

## Architecture

Everything hangs off two shared objects created once in `cli.main()` and threaded through every call:
- **`SessionState`** (`core/session.py`) — the single identity: `base_url`, `cookies`, `user_agent`, `impersonate` profile, optional `proxy` URL. The **same** UA/cookies/referer must reach curl-cffi, ffmpeg, and the browser or the CDN returns 403. `cli.main()` populates `user_agent`/`impersonate` from a randomly-picked entry in `core/personas.py` on every run (a pool of consistent UA+impersonate device/browser combos — desktop Chrome/Edge/Firefox/Safari + Android Chrome + iOS Safari) so the tool doesn't always present one fixed, shared fingerprint. `--tor` sets `session.proxy` to the local Tor SOCKS port (127.0.0.1:9050) after a quick reachability check; falls back to a direct connection with a warning if Tor isn't running.
- **`Network`** (`core/network.py`) — the only HTTP layer. Uses **curl-cffi** (Chrome TLS/JA3 impersonation), never stdlib `requests`. Retries 403/429/503 as `BlockedError` (with jittered backoff) and syncs cookies back into `SessionState`; it also seeds the curl client *from* `session.cookies` at construction, which is what makes `--cf-cookie` reach the wire. A 403 has two very different causes and conflating them misleads diagnosis, so `_is_challenge` splits out **`ChallengeError`** (subclass of `BlockedError`) for a Cloudflare JS challenge (`cf-mitigated: challenge` header, or `_cf_chl_opt`/`cf-browser-verification` in the body): TLS impersonation cannot pass it (solving it needs a real JS engine), so it is raised **immediately without retrying** and its message tells the user about `--cf-cookie`/`--tor`. Builds its default headers from `session.user_agent` (not a hardcoded constant) so persona rotation actually takes effect.

### Multi-site adapter layer

`core/sites.py` defines the `SiteAdapter` Protocol (`resolve_domain`, `search`, `suggest`, `get_episodes`, `build_stream`) and a `SITES` registry dict. Each module under `sites/` implements one site and calls `register(...)` on import; `sites/__init__.py` imports all of them so `--site {dizipal,hdfilmcehennemi}` (argparse `choices=SITES.keys()`) can dispatch generically. `catalog.py`'s `Series`/`Episode` dataclasses and pure list helpers (`match_episode`, `next_episode`, `seasons_of`, `episodes_in_season`) live in `core/models.py` and are re-exported from `catalog.py` for backward compat — those stay adapter-agnostic and are used as-is by every site. `Series.site` (adapter name) is stamped by each adapter's `search`/`suggest` — this is what lets a merged multi-site result list route back to the right adapter after the user picks one.

**`--site` is optional and changes `cli.main()`'s shape**: with `--search` (non-interactive automation) it defaults to `dizipal`, single adapter, unchanged from before. Interactively, if `--site` is *not* given (the default), `main()` connects to **every** registered site in parallel (`concurrent.futures.ThreadPoolExecutor`, via `cli._connect`) and calls `run_interactive(contexts)` with a `dict[site_name, (Network, SessionState)]`; `menu.prompt_search_series(contexts)` then queries all of them at once via `sites.search_all`/`suggest_all` (also parallel — sites have fully independent `Network`/`SessionState`, no shared mutable state, so concurrent calls are safe) and shows one merged, site-tagged result list. Passing `--site` explicitly (even without `--search`) pins back to the old single-site interactive flow (`contexts` with one entry) — this is also how you'd test one adapter in isolation. `run_interactive` re-resolves `net`/`session`/`adapter` from `contexts[series.site]` after every pick (not fixed for the whole session), so "yeniden ara"/"yeni arama" naturally stays multi-site. `--domain` only applies when `--site` is also given (ambiguous across sites otherwise, and ignored with a warning if not). The "kaldığın yerden devam" resume record now carries `site` too (`prefs.json`'s `resume.site`, defaults to `"dizipal"` for older records saved before this field existed).

**Tolerant search (`core/query.py` + `sites.search_site`)** — the site backends match **literally**: on hdfilmcehennemi, `spider-man` returns results while `spiderman` returns almost nothing (live-confirmed). We can't fix their index, so `sites.search_site` wraps every `adapter.search`: it runs the query as typed, and if the result list is thin (`< _ENOUGH_RESULTS`) or nothing scores well, it fires up to `query.MAX_VARIANTS` alternative spellings **in parallel** (punctuation/Turkish-char folding, compound split `spiderman`→`spider man`, noise-word stripping, longest/last word alone, prefix), then merges, dedupes and ranks. **Widening is skipped entirely when the query already matched a title outright** (`best_score >= query.EXACT_SCORE`) — "the last of us" scored 1.00 off a single result, and firing variants anyway is exactly what buried it under 16 `The Last …` titles. `query.rank` then applies three filters: `score`, `coverage` (multi-word queries only — letter-weighted fraction of query words present in the title; without it the widened net dragged in `Adam`/`Black Adam` for "orumcek adam"), and a tail cut (`LEAD_BAND`) that drops results trailing far behind a clear winner while always keeping at least `MIN_KEEP` rows so franchises/sequels survive. Ranking also decides the order of the merged multi-site list, so exact matches surface first regardless of which site answered.

**`score` is length-aware, and that is load-bearing.** It runs difflib over a folded+squashed form (hyphen/space/`ö`↔`o` differences cost nothing), but when the title merely *contains* the query the floor it gets is proportional to how much of the title the query explains (`_CONTAIN_FLOOR + 0.40 · len(query)/len(title)`). The earlier fixed `0.90` floor made the score **saturate**: every title containing the word got the identical 0.90, so "gibi" returned 29 results all tied and an exact match had no way to win — the user-visible "I type the series name and get other things". Two guards belong with it: `_clean` strips noise words (`türkçe dublaj`, `izle`, `1080p`) from *both* sides so a padded title isn't punished for length it doesn't own, and `alt_titles` splits hdfilmcehennemi's multi-language `name` (`"Kara Şövalye - The Dark Knight"`) on **space-delimited** dashes only, scoring against the best-matching part. Never add `:` to that split — `Spider-Man: No Way Home` would then score as an exact match for `spiderman`.

**Duplicates are collapsed at two levels, and both keep film/series apart.** Within Dizipal, every series is listed twice (`X` and `X Türkçe Dublaj`); `dizipal_adapter._collapse_dubs` folds those to one row (preferring the original; a dub-only title survives). It sits in the **adapter**, deliberately not in `catalog.search` — `catalog.find_counterpart` needs to keep seeing both records, and picking either row yields the same merged stream anyway since `merge.build_merged` resolves the counterpart itself. Across sites, `sites._dedupe_cross_site` (called by `search_all`/`suggest_all` before ranking) groups results by `query.keys` — folded, noise-stripped titles including multi-language name parts, so `"The Matrix 2 - The Matrix Reloaded"` matches `"The Matrix Reloaded"`.

**Catalog browsing (`sites.home_rows`/`sites.browse`, both via the shared `_collect` helper)** — home-screen rails and the "Diziler"/"Filmler" tab listings, for sites that implement the optional `home_rows`/`browse` adapter methods (not part of the `SiteAdapter` Protocol's required set — a site without them is just skipped, no stub needed). `_collect` fans a call out to every ready site in parallel and **bounds the wait to 8 seconds** (`concurrent.futures.wait(..., timeout=...)`, not the executor's own `with`-block join): with 5 sites now registered, one slow/unreachable one used to block the whole home screen for as long as that site's own retry/timeout budget took (measured: up to ~16s combined with the domain-resolution step below) even though the other 4 had already answered in under a second. A site that times out is simply missing from that call's result — nothing is cached as "failed", so it's retried normally next time. The Android bridge (`hayalet_app.home`) goes further and **pipelines** per-site domain-resolution with that site's own `home_rows` fetch inside one bounded pool (instead of two sequential bounded phases) — halves the cold-cache worst case; see `hayalet_app._connect_all`/`hayalet_app.home` in the Android app's Python bridge (outside this repo, junctioned in — see **Android build and device workflow** below) for the pattern if porting it back to the CLI's own `home`-equivalent ever comes up.

**`_PREFERRED_SITE` is a preference, not a filter, and the distinction is the whole point.** The intended split is *movies → hdfilmcehennemi, series → Dizipal*, and it used to be enforced as a hard filter: `dizipal_adapter.search` dropped every `Movies`-typed result. That made Turkish films **that exist only on Dizipal** (Sıfır Bir, Adana İşi, Çakallarla Dans…) completely unreachable — hdfilmcehennemi has none of them, live-confirmed, and the dropped records were perfectly playable (`get_episodes` → one synthetic episode, `build_stream` → a real `master.m3u8`). Now the split is applied only where the duplication actually occurs: when both sites carry a title the preferred one wins; when only one does, that record stands. **Both collapse keys include `catalog.is_movie`** — Dizipal lists `Sıfır Bir` as a series *and* as a separate film, and a title-only key would silently eat one of them. Every path uses it: `menu.prompt_search_series` → `sites.search_all` → `search_site`, `cli.run_cli` (`--search`) → `search_site`, and the Android bridge (`hayalet_app.search`) → `sites.search_all`. `--doctor` deliberately calls the raw `adapter.search` — it probes the site mechanism, not our tolerance layer. `query.py` is pure/network-free and covered by `tests/test_query.py`.

- **`sites/dizipal_adapter.py`** — a thin, zero-new-logic wrapper around `catalog.py`/`extractor.py`/`merge.py`/`resolver.py` (see pipeline below). `build_stream` = `merge.build_merged`.
- **`sites/hdfilmcehennemi_adapter.py`** — movies **and series**, no dub/original split (the master `.m3u8` already embeds Turkish + original audio as separate HLS renditions), so `build_stream` resolves a single source directly instead of merging two. Series episode pages use the **same** player chain as movie pages, so `build_stream` is shared verbatim; only `get_episodes` forks on `series.type` — for a `Dizi` it reads the page's schema.org **JSON-LD** (`containsSeason` → `TVEpisode`: `episodeNumber` + `url`, season taken from the `/sezon-N/` path), falling back to scraping `/sezon-N/bolum-M/` hrefs. TVEpisode blocks are matched one-by-one rather than `json.loads`-ing the whole document, because a page can carry several JSON-LD blocks and one malformed block would otherwise lose them all. The real `master.m3u8` URL is hidden behind a **"Dean Edwards packer"** JS blob (`_packer_unpack`, a=62 variant — reusable general algorithm) whose *payload* is further obfuscated by a custom "unmix" scheme, and the site has shipped (at least) two generations of that scheme:
  - **"gen1"** (`_unmix`/`_parse_ops`/`_apply_ops`/`_OP_RE`/`_MAGIC_RE`): reverse / ROT-N-letters / base64-decode steps whose **count and order randomize per page load** (confirmed across 15 live fetches, no two identical), parsed from the unpacked source in appearance order; final step is a numeric byte-mixing offset (`magic`/`offset`, also randomized but structurally fixed).
  - **"gen2"** (2026-09, `_extract_master_url_v2`/`_gen2_decode`/`_find_function_body`, `_GEN2_*` regexes): the packed script now embeds **two** decoder functions — one is a **decoy** shaped to look like gen1's array-call pattern (its output is never referenced), the other is **real**. Which is real is told apart by the embed HTML's `sources:[{file:X}]` — X names the real function's result variable — never by structural guessing. The real algorithm: splice two elements (OP marker string + KEY) out of the source array at positions derived from `arr.length`, hash KEY into three derived constants, apply OP's reverse/atob/ROT steps to the remaining payload in **reverse** order, shuffle it with an LCG-generated permutation, then XOR-stream-decode with the derived constants. All numeric constants are parsed from source via regex (never hardcoded) even though two independent live samples showed identical values — matching the file's existing "never assume, always re-derive" philosophy. `_extract_master_url` tries gen2 first, falls back to gen1 (`_unmix`) if gen2's regexes don't match. **The single most reliable way to verify or re-derive either scheme**: run the real unpacked JS in Node.js (`node --version` — available on the dev machine) and diff its output against the Python port byte-for-byte; hand-tracing the obfuscated JS is error-prone (a missed `*5` multiplier in the final XOR step once produced a wrong-but-non-crashing URL). If extraction breaks again, re-survey a few fresh `/rplayer/<hash>/` fetches before assuming a third generation — it may just be a gen2 constant/marker-character combination the current regexes haven't seen.
  - hdfilmcehennemi's **poster/thumbnail CDN also needs curl-cffi impersonation**, not just its page/API endpoints — a plain `HttpURLConnection` (as the Android app used for image loading) gets a flat 403 from the same host that serves 200s to curl-cffi. Also: some pages link `images/thumb/poster/<file>` (60×60px) or `images/list/poster/<file>` (200×300px) for the SAME image that exists at `images/poster/<file>` (400×600px) — the small variants exist and are usable, just blurry when stretched into a larger UI card.
- **`sites/diziyou_adapter.py`**, **`sites/fullhdfilmizlesene_adapter.py`**, **`sites/webdramaturkey_adapter.py`** — added later, each a self-contained single-file adapter following the same `SiteAdapter` Protocol; none has been deeply investigated/documented here yet (no extraction-scheme write-up like the ones above) — read the adapter itself before assuming its scraping/extraction quirks match another site's.

- **`sites/dizisol_adapter.py`** — a JSON API aggregator keyed by TMDB id. Each title lists several sources; `build_stream` probes them in priority order and takes the first real `#EXTM3U`. Source names come from the API, not code; `site::...` internal codes are skipped except `diziyou::<id>::`. Most sources need `Referer` + `Origin` (`media_headers`), and content marked `isPremium` is refused. Only public content endpoints are used, never `/api/admin/*`.
- **`sites/_dizipal_next.py`** — shared base class `DizipalNextAdapter` for sites running **Dizipal's Next.js engine** (a "Web Drama Turkey"/Dizipal clone): search `POST /api/bg/searchContent?searchterm=` → `{"response": <payload>}`, page data in `__NEXT_DATA__` → `pageProps.secureData`, episode list at `…RelatedResults.getSerieSeasonAndEpisodes.result[].episodes[]`, episode sources at `…getEpisodeSources.result[].source_content` (an `<iframe>`), player = pichive/NP_CONFIG (`_pichive`). The **only** per-site difference is how the `secureData`/`response` payload is decoded, so the base leaves `_decode(raw)` abstract and a subclass supplies it (`name`/`known_domain` too). Slugs are `dizi/<x>` · `film/<x>`.
  - **`sites/asyawatch_adapter.py`** — asyawatch.com (Asya/Kore/Çin). `_decode` = **plain base64 JSON** (payload is not encrypted on this build).
  - **`sites/selcukflix_adapter.py`** — selcukflix.app (yabancı dizi/film). Same engine, but the payload is **AES-256-CBC encrypted**: `_decode` = base64 → AES decrypt → PKCS7 → JSON, with key `base64(sha256("!!22xx!!90!!"))[:32]` and a **zero IV** — the **same key/scheme as dizisol** (re-derived live from the site's `_app` bundle's `aes-256-cbc` path). Two sites on one engine differ only by this layer.
- **`sites/dizimay_adapter.py`** — dizimay.pro (Kore/Çin/Asya/BL), a plain WordPress scrape: search `/?s=<q>` → `/dizi/<slug>/` cards, series page → `/bolum/<slug>-N-bolum/` links (no season in URL → season 1), episode page → `<iframe src="//ok.ru/videoembed/<id>">` handed to the shared ok.ru resolver. Asian-drama subs are burned into the video; no separate subtitle channel. **Its ok.ru content plays** (Asian dramas aren't copyright-struck on ok.ru).
- **`sites/dizibox_adapter.py`** — dizibox.live (yabancı diziler, WordPress "dbx18"). Was removed once for being **slow** — the cause was WordPress's `/?s=<q>` search (20s+ timeout); the fix is to fetch the full A–Z archive at **`/arama/`** (~4760 series, ~0.7s) once and filter it client-side. Series slugs sometimes carry an `-izle`/`-izle-N` suffix the episode URLs drop, so `get_episodes` strips it before scoping to the series' own slug (the series page's sidebar lists other shows' episodes). Player chain: episode page → a **single-quoted** `<iframe src='…/player/king/king.php?v=<hash>'>` (double-quote-only regex misses it) → inner iframe `dbx.molystream.org/embed/<id>` → `_molystream`.
- **`sites/yabancidizi_adapter.py`** — yabancidizi.news (film + dizi, custom "mofy" engine). Search is a fast `POST /search?qr=<q>` → JSON (`s_type` **"1"=film, "0"=dizi**; route to `/film/<slug>` vs `/dizi/<slug>`). The player: from a source button's `data-link`, **base64url it** (`+`→`-`, `/`→`_` — the site's JS does this) and GET `/api/ruplay/<tok>` (ok.ru sources) **and** `/api/drives/<tok>` (drive sources on `*.popcornvakti.net`); each returns an `<iframe>` → routed to `_okru` (ok.ru) or `_molystream` (popcornvakti). **Two gotchas, both load-bearing:** the `/api/*` endpoints require a cookie **`udys=<Date.now()>`** that the page's JS sets (`comolokko("udys", Date.now(), …)`) and are otherwise served empty (0 bytes) to a browserless client — `_udys()` supplies it as a `Cookie` header; and the site's `/ajax/service` stream flow (`videoGet`/`get_stream`) 520s at the origin, so it is bypassed entirely in favour of `/api/ruplay`·`/api/drives` (found by driving the real browser and reading the loaded `.player` iframe). Series still list episodes through the 520ing ajax, so a series falls back to whatever the main page offers; films work fully (verified: Venom → ok.ru, The Last Stand of Ellen Cole 2024 → popcornvakti, both to a real m3u8).
- **`sites/dizitivi_adapter.py`** — dizitivi.org (WordPress "diziplus"): search `/?s=<q>` → `/<slug>-izle/` cards, series page → `/<slug>-N-sezon-M-bolum/` (season+episode both in URL), episode page → `data-src="//ok.ru/videoembed/<id>"` → ok.ru resolver. **Caveat:** many of its ok.ru videos (popular foreign series) come back `copyrightsRestricted` from ok.ru itself — the adapter's parsing is correct but the content is dead at source, so `--doctor` can go red on restricted titles. Turkish shows reportedly use `erbvr.com` direct-mp4 (not wired yet).
- **`sites/trdizi_adapter.py`** — trdizi.im (WordPress "dizi", yerli diziler): search `/?s=<q>` → `/diziler/<slug>/` cards, series page → `/<slug>-N-bolum-izle/` links **scoped to the series' own slug** (the page's sidebar lists other shows' episodes — filtering by the base slug, derived by stripping `diziler/` and the `-son-bolum-izle` suffix, is load-bearing), episode page → `data-frame="…/player/<token>/"` → that player's config `"file"`. A `?source=legacy` frame carries a direct m3u8 (often twimg — **needs an empty Referer; the site's own referer 403s**); other frames are usually YouTube embeds, which hayalet doesn't play (clear `ExtractError`).
- **`sites/animecix_adapter.py`** — animecix.tv (**anime**, Türkçe fansub; yeni dikey). Saf JSON uygulama API'si, CF yok: arama `GET /secure/search/<q>?limit=20` → `{results:[{id,name,title_type,year,poster}]}` (`title_type` "movie"→Film, diğer→Dizi; `id` = titleId, `slug="t/<id>"`); bölüm kaynakları `GET /secure/episode-videos?titleId=<id>&episode=N&season=N` → fansub embed listesi. **Bölüm listesi yoklamayla çıkar:** başlık-detay ucu (`/secure/titles/<id>`) browserless istemciye cloaking yapar (id ne olursa olsun sabit default başlık döndürür) → sezon/bölüm sayısı ORADAN ALINMAZ; `episode-videos`'u **üssel + ikili aramayla** yoklayarak bulunur (`_last_episode`, ~log₂(N) istek; bölümler bitişik, boş yanıt = son — One Piece 1000+, Frieren 28+10, canlı doğrulandı). Oynatıcı önceliği: **tau-video** (`_tauvideo`) → **DÜZ MP4** (`kind="file"`); bölümde tau-video yoksa **uqload** (`_uqload`) → **HLS m3u8** (`kind="hls"`, bazen soft `.vtt` altyazı da gelir). **sibnet** (bu ortamdan 403 — muhtemelen WARP) ve **doodstream** (anti-bot) henüz desteksiz, ikisi de yoksa açık `ExtractError`. Anime altyazısı genelde gömülü.

The end-to-end Dizipal pipeline (all pure Python, no headless browser) — invoked by `DizipalAdapter`:

1. **`resolver.py`** — finds the current `dizipalXXXX.com` (cache → `config.KNOWN_DOMAIN` → incrementing scan), writes it to `.cache/domain.json`, sets `session.base_url`. The scan window is **deliberately wide** (`_SCAN = 24`): an observed rollover jumped 1561 → 1574 (13 steps) and the old 8-address window missed the domain entirely, surfacing as a bare "domain bulunamadı". Widening is affordable because `_scan_reachable` probes the range **in parallel** (`_SCAN_WORKERS` threads, one throwaway `Network` each — a single curl-cffi client is not thread-safe, and the copied `SessionState` keeps dead candidates' cookies out of the shared one) with `retries=1` and a short `_SCAN_TIMEOUT`; a dead host must not cost 3 attempts × 20s. The priority candidates (cache, `KNOWN_DOMAIN`) are probed with those same cheap settings because they are only a **fast path** — the scan range starts at the seed's number, so missing them loses nothing. **The scan is seeded from the last domain that actually worked, not from `KNOWN_DOMAIN`** (`_stale`/`_record`): past its 6h TTL the cache record stops counting as "validated" but is still probed as a priority candidate *and* becomes the scan origin whenever it is ahead of `KNOWN_DOMAIN`. Losing it is what broke the tool in the field — `KNOWN_DOMAIN` sat at 1574 from August while the site reached 1822 by late October (~3.4 numbers/day), so one day without running the tool expired the cache and the scan restarted 248 steps behind. For the same reason the window **widens with the seed's age** (`_DRIFT_PER_DAY = 5` per day on top of `_SCAN`, capped at `_SCAN_MAX = 240`; measured: 240 candidates ≈ 12s, so a two-month-old seed still self-heals in one run), and reachable scan hits are tried **highest number first** — the live domain is always the newest, while the stale addresses behind it stay up as search-dead mirrors (measured: 1584–1592 all answered 200). A `--domain` override is the exception: it keeps full retries/timeout, since a user-pinned address must not be skipped over a transient hiccup and silently replaced by a different domain. **A candidate is accepted only if `_search_works` confirms `SEARCH_ENDPOINT` returns real JSON** — an HTTP 200 homepage proves nothing, because in blocked regions the reachable address is often a **front-page mirror** that serves the same HTML for every path and answers the search POST with that same HTML (this exact failure shipped once: the mirror was cached as a working domain and search died on a bare `JSONDecodeError`). `_mirror_origin` recognizes such a front by the `var ORIGIN="https://dizipalNNNN.com"` its own JS carries, tries that origin first, and names it in the `ResolverError` when nothing validates. Nothing is written to `.cache/domain.json` until validation passes. This incrementing-domain-scan strategy is Dizipal-specific and does not generalize (`resolver.ResolverError` itself is reused generically — `HDFCAdapter.resolve_domain` raises it too on an unreachable static domain).
2. **`catalog.py`** — `search()` (POST `/bg/searchcontent`, needs the `cValue` token scraped from the homepage — cached per-process, see below) and `get_episodes()` (scrapes `/bolum/...-SxE` links). Also owns dubbed↔original **counterpart matching** (`is_dubbed`, `find_counterpart`, `match_episode`) and the fuzzy "şunu mu demek istedin" fallback (`suggest`).
3. **`extractor.py`** — the crypto chain: episode page → `data-rm-k` encrypted JSON → **`utils.decrypt_rmk`** (CryptoJS AES + PBKDF2-SHA512, params in `config.py`) → iframe → `openPlayer('<playList>')` + embedded Turkish `.vtt` → `source2.php` → real `master.m3u8`. Raises `DeadSourceError` (subclass of `ExtractError`) when the player host is a **dead/parked domain** (CHEQ→RTB→domain-parking, common on "Türkçe Dublaj" embeds) — this is *not* anti-bot, there is genuinely no video behind it.
4. **`merge.py`** — resolves **both** the dubbed and original versions of an episode and combines them into one `MergedStream`: original video + [Turkish-dub audio, original audio] + Turkish subtitle. This is the object `watch`/`download` consume, built via `adapter.build_stream(...)` (a single call now covers `extract`/`watch`/`download` alike — no separate/duplicate extraction path). When the dub source is dead it gracefully falls back to just the original.
5. **`proxy.py`** — the crux of playback. A local `ThreadingHTTPServer` (`HLSProxy`) that players/ffmpeg connect to on `127.0.0.1`. It refetches every playlist/segment through curl-cffi (solving the 403), rewrites playlist URLs to point back at itself, serves disguised `.jpg` segments as `.ts`, and **injects the Turkish subtitle as an HLS `SUBTITLES` channel** into the master so every player sees it natively. It can also host **synthetic** playlists (`virtual()`) — the multi-audio master built by `merge` — and serves the `/player.html` hls.js watch page (hls.js bundled locally at `hayalet/assets/hls.min.js`). Fully site-agnostic. **The player page (`_PLAYER_TEMPLATE`) has non-obvious workarounds — read these before touching it:** (a) subtitles are rendered by our **own `#capOverlay` div**, not `video::cue` — we force the hls.js text track to `mode='hidden'` (so the browser draws nothing) and poll `activeCues` ourselves, because native cue styling (size/color/bg) is unreliable across browsers and rendering both caused doubled subtitles; (b) `v.blur()` on the video's `focus` event — otherwise native `<video controls>` steals keyboard focus and the browser's built-in shortcuts swallow our keys (arrow-seek would double to ~20/40s); (c) the native fullscreen button is CSS-hidden and fullscreen goes through our own button / `f` key on `#wrap` (native FS fullscreens the `<video>` alone, losing the gear/menu/subtitle overlay); (d) controls auto-hide via a mousemove + inactivity timer (not `:hover`, which never hides in fullscreen). The extracted JS must pass `node --check`; watch for literal `\n` inside the Python triple-quoted template (must be `\\n` to reach JS as an escape).
6. **`actions.py`** — `watch()` builds a synthetic master, opens the browser at the proxy's player page (a single top-right ⚙ menu gives quality/audio/subtitle selection + subtitle size/color/background). `download()` runs a **single ffmpeg pass** mapping the **highest-quality video variant** (resolved via `list_variants`[0] — never the raw master, since ffmpeg's default variant pick is the *first*, which on some sites e.g. hdfilmcehennemi is the **lowest**) + every audio track (language/title tagged) + softsubbed Turkish subtitle → `.mp4` (single audio) or `.mkv` (multi-audio or subtitle), with live progress from `ffmpeg -progress`. Site-agnostic. **Download destination** (`cli._out_dir`/`_file_title`): base is the user's `~/Downloads` (`config.DOWNLOAD_DIR = Path.home()/"Downloads"`); a **series** goes to `Downloads/<Series>/<Series> - SxxExx.mkv` (episodes grouped in one subfolder), a **movie** goes straight to `Downloads/<Movie>.mkv` (single file, no subfolder) — the split is driven by `catalog.is_movie(series)`.

**Automatic subtitle↔audio alignment (`core/subsync.py`)** — measures whether the subtitle is drifted against the audio and shifts it, with no user input. ffmpeg's `silencedetect` gives the speech spans (knowing *where* speech is suffices; nothing is transcribed), the `.vtt` gives the cue spans, both become bit masks binned at `BIN_MS`, and ±`MAX_LAG_S` of shifts are scored with `(speech & cues).bit_count()` — pure Python ints, no numpy/FFT, the whole sweep is milliseconds. **The score is deliberately asymmetric** ("is there sound where the subtitle speaks?", never the reverse) so a car horn, music or an explosion — extra sound with no cue — costs nothing; only a cue over silence is punished. In `download()` the measurement runs **in a thread parallel to the download**, so the measured-common case (subtitle already aligned) adds zero time; only a real shift triggers a second, subtitle-only `-c copy` remux at the end (`_shift_embedded_sub`). ffmpeg is only how the *desktop* obtains those spans — the decision code is `analyze_spans(speech_spans, vtt, window)`, which takes spans from anywhere (see **Android: the same alignment without ffmpeg** below). The Android downloader (`hayalet_dl.py`, a pure-Python segment fetcher that writes a local HLS tree with a `subs.vtt` sidecar) aligns too, after the download: `_altyaziyi_hazirla` concatenates the first `WINDOW_S` of the already-downloaded original-audio segments, calls the same Java `AudioScan.tara` through Chaquopy (`from java import jclass` — hence `AudioScan` and `tara` are `public`), runs `analyze_spans`, and rewrites `subs.vtt`; it also prepends the `X-TIMESTAMP-MAP` (see below), because offline playback is the same local-HLS path and had the same early-subtitle error. Either step may fail without failing the download. Local playlists are read with `m3u8.loads` on the file text — `m3u8.load(path)` treats a Windows `C:\…` path as a URL (caught by the desktop test).

**Frame-rate mismatch (`subsync.RATES`).** A subtitle timed for a different frame rate drifts *progressively* (25↔23.976: ~2.6 s per minute), which no constant shift fixes — the old code refused such cases (safe) or applied a partial constant. `analyze_spans` now also tries the physically possible rates only (25/23.976, 24/23.976, 25/24 and inverses), scaling cue times before the ordinary offset sweep; `SyncResult.rate` and `shift_vtt(vtt, offset, rate)` carry the result (`t → t·rate + offset`), and every consumer passes it on (desktop remux, `/subsync` JSON + `applySubOffset` in the player page, the Android bridge and downloader, the toast). **The gate's third condition is the important one**: besides `RATE_MIN_Z`/`RATE_MIN_MARGIN`, a rate must beat the constant-offset z by `RATE_MIN_GAIN`. On six *correct* live subtitles another rate came within +0.6 z of 1.0, and on The Last of Us the 1.001 rate passed both absolute thresholds with a gain of only +0.1 — without the gain rule a correct subtitle would be stretched by ~2.7 s over the episode. Verified on Rick and Morty S1B1 audio: four deliberately stretched subtitles (incl. one with an extra +3 s) were undone over the *whole* episode within 0.02 s, the real one untouched, 20 scrambled ones rejected.

`watch()` uses the same measurement through `_start_subsync`, which runs it in a thread and parks the answer in `proxy.subsync`; the browser polls the proxy's `/subsync` endpoint every 2s until `ready`, so **playback never waits for the measurement**. The player then shifts the *already-loaded* cues in place (`applySubOffset`): `TextTrackCue.startTime/endTime` are mutable and `activeCues` recomputes itself, so the fragile caption renderer (`pollCaptions`/`#capOverlay`) needed no change at all — that is why this route was chosen over re-fetching a shifted `.vtt`. Two hazards are handled explicitly: cues carry a `_sy` marker because `applySubOffset` is called from the 120ms caption poll and a double shift would drag the subtitle further out every tick, and newly arrived cues are picked up (hls.js appends subtitle cues progressively) by rescanning only when a track's cue count changes. `_start_subsync` is re-armed per episode (`loadStream` resets the client side, `_next_handler` the server side) since the offset is episode-specific, and it builds its **own** `Network` — one curl-cffi client is not thread-safe and this runs alongside the browser thread that serves `/next`. Verified in headless Chromium against the real player page: cues at 10–12s/20–22s moved to 6–8s/16–18s for a −4.0s offset, did not move again on later ticks, and a cue added afterwards was shifted too.

**Android: the same alignment without ffmpeg.** The phone has no ffmpeg, so only the *speech-span extraction* is reimplemented; thresholds, scoring and the confidence gate stay in `subsync.analyze_spans`, shared verbatim. `AudioScan.java` (in the Android project) decodes the audio with MediaExtractor + MediaCodec and reproduces `silencedetect`'s criterion: one-pole band-pass at 200/3000 Hz, 20 ms frames, a frame is silent when its **peak** sample is below −25 dBFS, and only silence runs of ≥0.25 s split speech. **The criterion is peak, not RMS, and that is load-bearing** — RMS at the same threshold measured 11% fill against ffmpeg's 70% and every decision came out wrong. Two cheap routes were measured and rejected before this one: a map built from AAC frame *sizes* without decoding at all (could not separate a real subtitle from a fabricated one), and the RMS variant above. Do not retry either.

The split is `hayalet_app.subsync_prepare()` (downloads `WINDOW_S` seconds of the non-Turkish audio rendition's segments into one cache file, fetches the `.vtt`, keeps both in `_sync`) → `AudioScan.tara()` in Java → `hayalet_app.subsync_finish(spans)` (runs `analyze_spans`; on a real shift it shifts the VTT and rebuilds the master via `_build_watch_master(..., sub_text=…)`, whose `sub_text` kwarg hosts a ready string through `proxy.virtual` instead of proxying the remote URL). `PlayerActivity.hizalamayiBaslat()` drives it on a background thread **15 s after playback starts** (the 10 MB measurement download must not race the video's initial buffering). When a shift is real the corrected master is re-loaded at the current position — ExoPlayer cannot shift already-parsed HLS text cues the way hls.js can, so this one brief rebuffer is the price.

**Two things about that reload are easy to get wrong and both were seen on a real device.** (a) It is *deferred while subtitles are off*: the answer is parked in `hizaliKaynak` and the swap happens the moment the user picks a subtitle from the menu (`showSubtitleSubMenu`), so someone watching the Turkish dub with captions off is never interrupted for a correction they cannot see — and the measured default on this app *is* off, since Media3 selects no text track unless system captioning or a preferred language says so. (b) The subtitle selection does **not** survive the reload on its own: the menu selects a track with `TrackSelectionOverride`, which is bound to a `TrackGroup` *object*, and preparing a new `MediaItem` rebuilds those groups — so the override silently stops matching and the user's subtitle turns itself off, which is the exact opposite of the feature's point. `bekleyenAltyazi` carries the chosen track's *label* across the reload and `onTracksChanged` re-applies it. Three further guards: a generation counter (`hizalamaKusagi`) so a previous episode's late answer is never applied, a skip unless `currentUrl` is the local proxy (a downloaded `file://` or a trailer has no bridge context and would be judged against the *previous* episode's subtitle), and no reload while casting.

Measured, not assumed — the Java port was checked against the Python one on identical PCM (344 spans, 0.0000 s deviation), then the real Android path (MediaCodec on the emulator) against ffmpeg's decode of the same episode (344 spans, 0.0000 s, fill 0.6864, 6.8 s for 600 s of audio on a software x86 decoder). End to end against live Dizipal through the real bridge: the genuine subtitle was left alone (offset 0.0, z 10.0), a deliberately +4 s shifted one was detected at −4.0 and the corrected `.vtt` was confirmed to come back off the proxy at the original cue times, and a fabricated subtitle was refused (z 2.9). **The 600 s window is required**: at 300 s the gate failed at every threshold tried, with ffmpeg's own spans too.

Finally verified on the phone itself (Galaxy S24, arm64 — note the emulator **cannot** run this APK, see the memory note on device-free verification): S1E1 gave the same 344 spans as the desktop and was left alone; with a deliberate +4 s shift planted through the debug hook below it reported −4.0, swapped at the current position, showed the toast and kept the subtitle on; a second episode (S1E2, 245 spans, fill 0.753) was measured independently and correctly left alone. Decode cost on-device: ~14–18 s for 600 s of audio while video was playing.

**Debug hook** (the only way to exercise the *correction* path on a real device, since real subtitles are usually already aligned): drop a file named `subsync_test_kaydir` in the app's cache dir containing a number of seconds, and `subsync_prepare` shifts the fetched subtitle by that much before measuring — the measurement must then find the opposite shift and undo it. `adb shell "run-as com.hayalet.test sh -c 'echo 4 > /data/data/com.hayalet.test/files/hayalet-cache/subsync_test_kaydir'"`.

**A second, different subtitle error lives in playback, not in the file — and `subsync` can never see it.** On the phone (Media3/ExoPlayer) subtitles showed ~0.7–0.8 s *early* in every Dizipal title even though the `.vtt` was measured aligned to the audio (Sherlock S1B1: median cue-vs-speech +0.12 s over 77 lines). Cause: the injected `.vtt` carried no HLS `X-TIMESTAMP-MAP`, while the media segments' first PTS is not 0, so the player guessed the mapping. The desktop player had it worse and *exactly* measurable from inside headless Chromium (`TextTrack.cues[i].startTime` vs the file): **hls.js placed every cue early by the segment's start PTS** — Dizipal −1.400 s on all 1364 Sherlock cues, hdfilmcehennemi −0.101 s on all 1763 Interstellar cues. **The value to map is the *earliest* PTS among all streams in the first video segment, not the video's**: hdfilmcehennemi segments carry video at 0.184 s and muxed audio at 0.101 s, the player's timeline starts at the earlier one, and mapping to the video's value over-corrected to +0.083 s (measured). Dizipal segments hold video alone at 1.4 s, so the distinction never showed there. Fix: `actions._video_first_pts` reads the head of the first video segment (`Range: bytes=0-131071`, one retry; `proxy.first_pts` returns the per-PID minimum) and `_build_watch_master` stores it in `proxy.vtt_pts` on every non-`sub_text` build (so it is re-read per episode, desktop `watch()`/`/next` and the Android bridge alike), and the proxy prepends `X-TIMESTAMP-MAP=MPEGTS:<pts·90000>,LOCAL:00:00:00.000` to every `.vtt` it serves, proxied *and* virtual (`add_timestamp_map`) — the virtual path matters because a subsync correction re-hosts the shifted subtitle there. If the PTS cannot be read, nothing is added and behaviour is unchanged. Verified on-device by pausing at chosen positions and reading the rendered cue against the file's cue list: before, the *next* line was already on screen at gaps (≥0.64–0.84 s early); after, both an "is it early" probe (next cue 0.33 s ahead → not shown) and an "is it late" probe (current cue started 0.27 s earlier → shown) passed, i.e. within ±0.3 s; later 20 discriminating probes over Sherlock, TLoU, Rick and Morty and Interstellar all passed, the tightest at 0.11/0.19 s. On desktop, with the map, every cue landed at **+0.000 s** on both sites. Media3 showed roughly *half* the PTS (0.7 vs 1.4) without the map — the fix is verified on both players, but Media3's exact guessing rule was not pinned down. `tests/test_vtt_map.py` locks in the per-PID minimum, the fake-image-header skip, and the header insertion (BOM/CRLF, no double insert). hdfilmcehennemi's separate *Turkish dub* rendition starts at 1.8–2.8 s while the original starts at 0.101; this is **not** an audio offset — decoded with `-copyts` and compared on the PTS timeline the dub matches the original within 0.1 s (Interstellar, Matrix; z≈8), i.e. the dub file merely has its leading silence trimmed and players align by PTS. Don't re-investigate.

**Its confidence gate is the hard part, and the obvious statistic is the wrong one.** Absolute overlap does *not* discriminate: with 70% of the audio timeline non-silent, deliberately scrambled subtitles (real cue count and durations, random positions) still score 0.717–0.730 against the true subtitle's 0.742. What separates signal from noise is how far the peak stands out from the *whole* correlation curve, `z = (peak − median) / MAD`, together with the gap to the best rival at least `RIVAL_GUARD_S` away. Both thresholds were set by measuring a noise floor (scrambled / time-reversed / interval-mangled subtitles) rather than guessed: correct answers scored margin 0.031–0.042 and z 5.7–13.9, fabricated ones 0.0003–0.0074 and 2.1–3.5. Two traps are baked into the constants: `RIVAL_GUARD_S` must stay wide (cues run 2–3 s, so at 1 s the "rival" was still the same peak's own skirt) and the margin must *not* be read as an absolute difference that grows with data — on saturated audio it *shrinks* as the window grows (0.031 → 0.016 from 600 s → 1320 s) and was rejecting correct answers. Verified live end to end: a real episode whose subtitle was artificially shifted +4.0 s was detected at −4.0 and restored to its exact original cue times (0.000 s deviation), while the genuinely aligned original was correctly left untouched.

**Dizipal moved to Next.js (2026-11), so steps 2–4 above now describe the fallback path.** Search is `POST /api/mj` with JSON `{"action": "searchContent" | "searchContentFullText", "params": [query]}` and a mandatory `Origin` header (403 without it; queries under 3 letters get 400 `invalid-params`). Slugs are `dizi/<x>-dizi-izle` / `film/<x>-film-izle`; episode links live mostly in the page's escaped `self.__next_f.push` data, not in `<a>` tags, and appear both relative and as `http://<domain>/…`. The page's `player` object carries `enc` (same AES/PBKDF2 scheme) and its own passphrase `k`; decrypting gives the iframe, whose `window.NP_CONFIG` holds `sources[0].master` and `subtitles[].url` (`extractor._page_player`/`_np_config`). Dub is no longer a separate record: the master usually already holds Turkish + original audio, so `merge.build_stream` resolves one page and fetches the dub page only when no Turkish track exists, falling back to `build_merged` for an old-style page. `browser_fetch` (the Android `source2.php` hook) is not reached on this chain, and the phone path through the new chain has not been verified yet. Covered by `tests/test_dizipal_nextjs.py`.

The interactive flow (`cli.run_interactive`) branches on `catalog.is_movie(series)`: a **movie** skips season/episode selection entirely and gets a flat `menu.prompt_movie_action` (İzle / İndir / Yeni arama / Çıkış) acting on the single synthetic episode (`cli._movie_flow`); a **series** keeps the season → mode → episode(s) flow. Result-list type labels are Turkish-ified (`menu._type_tr`: Series→Dizi, Movies/Film→Film) and search runs under a spinner.

Supporting: `subsync.py` (**automatic subtitle↔audio alignment** — see below), `m3u8_parser.py` (variant/audio-track parsing via the `m3u8` lib — fully generic HLS parsing, used by every adapter), `menu.py` (questionary interactive prompts, adapter-parameterized), `logs.py`, `utils.py` (crypto + heuristics + `safe_filename`), `personas.py` (device/browser fingerprint rotation), `prefs.py` (`.cache/prefs.json` — quality/resume persistence, plus the per-host `cf` record: `cf_clearance` cookie **and** the UA it was issued to, stored together because Cloudflare binds one to the other — `save_cf`/`load_cf`/`forget_cf`).

## Working on this codebase — key facts

- **Uzaktan ayar / APK'sız düzeltme (`core/remote.py`).** Kırılgan site sabitleri (domain, endpoint, regex, kripto tohumu) APK yayınlamadan güncellenebilir: herkese açık bir JSON'dan (`REMOTE_CONFIG_URL`, boşsa KAPALI) açılışta çekilir, `.cache/remote_config.json`'a yazılır; adaptör `remote.get("<site>.<anahtar>", GÖMÜLÜ_VARSAYILAN)` ile okur. **Güvenlik ağı:** ulaşılamaz/bozuk/URL boşsa her zaman gömülü değere düşer (bugünkü davranış), çekme ARKA PLANDADIR (açılışı bloklamaz → taze değer bir sonraki açılışta), uzaktan KOD çalıştırılmaz (yalnız düz veri). Şu an bağlı anahtarlar: `selcukflix.key_seed` (AES tohumu — site anahtarı döndürürse buradan düzeltilir) ve `<site>.known_domain` (animecix/dizibox/dizimay/yabancidizi/asyawatch/selcukflix/webdramaturkey). Yeni bir sabit eklemek: adaptörde `remote.get("site.x", VARSAYILAN)` yaz, örnek dosyaya (`remote_config.example.json`) anahtarı ekle. Örnek dosya herkese açık bir Gist'e konur, ham adresi `REMOTE_CONFIG_URL`'e yazılır (kod repo'su PRIVATE kalabilir; config'te sır yok). Testler: `tests/test_remote.py` (varsayılana düşme, cache okuma, bozuk cache). `remote._data` modül-seviyesi durum → testte `_reset_for_test()` ile sıfırlanır (yoksa sızar).
- **`config.py` is the single source of truth for Dizipal specifically** (not the other sites — each adapter under `sites/` owns its own constants/regexes inline). When Dizipal changes, you edit config, not code:
  - `RMK_PASSPHRASE` / `RMK_ITERATIONS` / `RMK_KEYSIZE` — the `data-rm-k` decryption params, extracted from the site's `app-dizipals.js`. If the site rotates its bundle, decryption breaks and `RMK_PASSPHRASE` is what needs re-extracting.
  - `SELECTORS` — regexes for the encrypted block, `/bolum/` links, and slug→(season,episode). Brittle by nature; update here when scraping breaks.
  - `KNOWN_DOMAIN` — the resolver's **floor**: the scan origin is `max(KNOWN_DOMAIN, last working domain in the cache)`, so on any machine that has ever resolved successfully this constant stops mattering and bumping it is a cold-start optimization. It is still the only seed on a **fresh install** (no cache yet), so letting it rot by months makes first-run resolution fail outright — bump it when you notice the gap.
  - `SEARCH_ENDPOINT`, `USER_AGENT`, `IMPERSONATE`, `AD_INTERCEPT_DOMAINS`.
  - `catalog._cvalue_cache` — the search token is fetched once per process (not per search call) to cut redundant homepage requests; it's an in-memory dict keyed by `base_url`, never persisted.
- **curl-cffi only** for HTTP that touches the CDN/site — never stdlib `requests` (it gets 403'd on TLS fingerprint). Both Dizipal and hdfilmcehennemi were confirmed to need TLS impersonation (plain `WebFetch`/`requests` gets a 403 on either); hdfilmcehennemi's **image CDN** needs it too, not just its pages/API (see the poster bullet above) — the Android app's `Cover.java` learned this the hard way and now falls back to a curl-cffi-backed Python bridge (`hayalet_app.fetch_image`) per-host once a plain request 403s.
- The referer must propagate through the proxy for multi-source merges — proxied URLs carry a base64 `&r=` referer that sub-requests inherit (`HLSProxy.proxied` / `_rewrite`).
- Windows-first: `baslat.bat` forces UTF-8 (`chcp 65001`, `PYTHONUTF8=1`); `cli.py` reconfigures stdout/stderr to UTF-8 for Turkish/emoji output.
- The CHEQ/dead-source diagnosis (see `DeadSourceError` in Architecture above) and the ad-blacklist/subtitle heuristics both trace back to `reference/örnek eklenti/` (not tracked in git, local-only) — consult it before changing subtitle/ad detection logic. This only applies to Dizipal.
- Anti-detection posture (both sites): random device/browser persona per run (`personas.py`), jittered retry backoff and inter-episode download pacing (`network.py`/`cli._run_downloads`), no persisted cookies across runs, optional `--tor`. This is a best-effort, free-only posture, not a guarantee.

## Android build and device workflow

The Native Android project is outside this repository at
`C:\Users\Public\hayalet-android`. Its Python source is synchronized with this
repository's `hayalet` package through a junction, so Python changes must be
included with a fresh APK build (no copy step — editing this repo's `hayalet/`
IS editing the APK's Python source).

**What the app currently does** (all in Java + a thin Python bridge, no XML
layouts — everything is built in code; see `Ui.java` for the design system):
home-screen rails per site + a local-only "kaldığın yerden devam" (resume)
rail, search across every site at once, season/episode browsing, an ExoPlayer-
based player (pinch-to-zoom anchored to the touch point, Picture-in-Picture via
`onUserLeaveHint`, a `MediaSession` for headset/Bluetooth media-button
control), background downloads with a foreground service, and long-press
card actions (remove / jump to the title's own page without re-searching).
The Python bridge (`app/src/main/python/hayalet_app.py`, junctioned but its
own file — not part of this repo) is a thin JSON-in/JSON-out wrapper: no
business logic lives there beyond gluing Java calls to the `hayalet` package's
existing adapters/pipeline. `Cover.java` owns poster loading — it downsamples
on decode (never caches full-resolution bitmaps), and for hosts whose plain
`HttpURLConnection` gets 403'd (see the hdfilmcehennemi poster-CDN note above)
falls back to `hayalet_app.fetch_image` (a curl-cffi-backed bridge call) after
learning that host needs it once, rather than eating the failed attempt on
every single image. Detailed session-by-session findings (what broke, why, and
how it was verified) live in this machine's Claude memory under this project,
not here — check there before re-diagnosing something that looks familiar.

Use Java 17 and the cached Gradle 8.9 distribution:

```powershell
$env:JAVA_HOME = "C:\Users\Public\android\jdk\jdk-17.0.20+8"
Set-Location "C:\Users\Public\hayalet-android"
& "C:\Users\Public\android\gradle\gradle-8.9\bin\gradle.bat" clean assembleDebug
```

The APK is
`C:\Users\Public\hayalet-android\app\build\outputs\apk\debug\app-debug.apk`.
Use the Android SDK ADB at
`C:\Users\Public\android\sdk\platform-tools\adb.exe`. The phone's wireless
debugging port changes; read it from the phone and set `$serial` accordingly,
then run:

```powershell
$adb = "C:\Users\Public\android\sdk\platform-tools\adb.exe"
$serial = "192.168.1.46:<current-port>"
& $adb connect $serial
& $adb -s $serial install -r --streaming "C:\Users\Public\hayalet-android\app\build\outputs\apk\debug\app-debug.apk"
& $adb -s $serial shell am force-stop com.hayalet.test
& $adb -s $serial shell monkey -p com.hayalet.test 1
```

Verify installation with
`adb -s $serial shell dumpsys package com.hayalet.test`. Do not assume an old
APK is current: always check `lastUpdateTime` after installation.
